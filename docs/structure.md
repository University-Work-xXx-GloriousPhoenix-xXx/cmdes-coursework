# Структура коду

Рішення `code/CourseWork.slnx` (.NET 10) складається з двох проєктів:

- **PetriObj** — бібліотека імітації Петрі-об'єктних моделей, незалежна від задачі.
- **MainlineChannel** — консольна програма з моделлю магістрального каналу (завдання B10), побудована на PetriObj.

```
Program ──► MainlineModel ──► Parameters, Results
                 │
                 ▼
   PetriObj:  Model ──► PetriObject ──► Transition ──► Place
                                   Dist, SampleStatistics
```

Залежність одностороння: модель використовує бібліотеку, бібліотека про модель нічого не знає.

## PetriObj

| Клас | Призначення |
|---|---|
| `Place` | Позиція мережі Петрі: кількість маркерів, середнє за часом і максимум. Ототожнення позицій різних Петрі-об'єктів — це один і той самий екземпляр `Place`. |
| `Transition` | Часовий багатоканальний перехід із затримкою та пріоритетом. Дуги: `In` (вхідна), `Info` (інформаційна — маркери перевіряються, але не віднімаються), `Out` (вихідна). Статистика: середня кількість зайнятих каналів (`MeanBuffer`), лічильники входів/виходів. Події `OnEnter` / `OnExit`. |
| `PetriObject` | Петрі-об'єкт — іменований набір переходів. `Output(t)` — вихід маркерів із переходів, `Input(t)` — вхід маркерів, доки є переходи з виконаною умовою запуску (конфлікт — за пріоритетом, при рівних — випадково). |
| `Model` | Петрі-об'єктна модель і алгоритм імітації 3.4: просування часу до найближчої події → вихід маркерів → вхід маркерів до стабілізації. Накопичення статистики, відкидання перехідного періоду (`warmup`), протокол подій (`Trace`). |
| `Dist` | Генератори затримок у позначеннях посібника: `Const(d)`, `Unif(d, s)` — рівномірний на (d − s, d + s). Використовують спільний `Random` моделі, тож прогін відтворюється за seed. |
| `SampleStatistics` | Статистика вибірки (алгоритм Велфорда): кількість, середнє, СКВ, мінімум, максимум. |

## MainlineChannel

| Клас | Призначення |
|---|---|
| `Parameters` | Вхідні змінні: параметри затримок надходження, передачі, напрацювання на відмову, ремонту, запуску резервного каналу; прибуток з повідомлення, штраф, приріст напрацювання `K`. Значення за замовчуванням — з умови завдання. |
| `MainlineModel` | Побудова моделі за схемою: Петрі-об'єкти `Generator`, `Channel` (один метод для основного й резервного каналу), `BreaksRepair`; спільні позиції Storage, Main active, Transfer active, Extra active. Через події переходів веде чергу моментів надходження повідомлень і рахує час передачі кожного повідомлення. `Run` повертає `Results`. |
| `Results` | Вихідні змінні прогону: передано повідомлень (основним / резервним каналом), кількість і частота переривань, завантаження каналів, готовність основного каналу, черга в накопичувачі, прибуток, характеристики часу передачі. |
| `Program` | Точка входу: розбір аргументів, запуск прогону, друк результатів. |

## Запуск

```
cd code
dotnet run -c Release --project MainlineChannel -- --time 1000000 --warmup 5000 --k 0 --seed 1
```

`--trace` — вивести протокол подій (для короткого прогону, наприклад `--time 60`).
